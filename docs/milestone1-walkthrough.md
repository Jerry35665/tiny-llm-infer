# M1 通俗版导学 —— 你到底要造一台什么机器

> 配合 `milestone1-forward.md`（操作手册）一起看：那份是"怎么做"，这份是"在做什么、为什么"。
> 看不懂手册里某一步的时候，回来找对应的比喻。

## 1. 大局观：M1 在造什么

一个 LLM（比如 Qwen2.5-0.5B）本质上是一台**条件概率机器**：

```
输入几个词  →  机器运转一次（前向 forward）  →  输出 151936 个分数
                                              （每个分数 = "下一个词是它"的可能性）
```

ChatGPT 一个字一个字往外蹦，就是因为这台机器被反复运转：预测下一个词 → 拼回去 → 再预测下一个 → 循环。**M1 的目标就是把"机器运转一次"的完整流水线亲手造出来**。造好之后，M2 才加"循环往外蹦字"，M3 把它提速，M5 让它同时服务多个人。

你已经会写 GEMM、会写单个算子（实习经历），M1 是把它们**串成一台完整的机器**：第一次要让 24 层、上亿个数字接力计算，任何一环错一点，最后全是乱码。所以 M1 的真正主题不是"写算子"（你写过），而是——

> **怎么在一条 24 层长的流水线上，证明自己没写错。**

这就是"逐层对拍"方法论，下面第 4 节细讲。

## 2. 一次 forward 的"流水账"（每个算子在干什么）

拿金标准的第一个句子举例：`"The capital of France is"`。
tokenizer 把它变成 5 个整数（比如 `[464, 3139, 288, 4881, 318]`，M1 阶段直接从 meta.json 拿，不用自己实现）。后面所有计算，都是对这 5 个整数做的事情。

### ① Embedding：查字典

每个 token id 去一张 151936 行 × 896 列的大表里查出自己那一行，变成一个 **896 维向量**。

- 形象：每个词领到一张"身份证"，上面 896 个数字刻画它的语义（"法国"和"巴黎"的身份证数字会比较接近——这是训练出来的）。
- 你要写的 kernel：`out[r,:] = table[tokens[r],:]`，纯查表拷贝，第一个练手。
- 为什么不是 1 个数字：1 个数字表达不了语义；896 个数字组成的"坐标"才能把几十万个词彼此区分开。

### ② RMSNorm：调音量

对每个位置的 896 维向量，除以它们的"均方根"再乘一组缩放系数 `w`：

```
out = x / sqrt( mean(x²) + 1e-6 ) * w
```

- 形象：24 层接力过程中，数值会有的层偏大有的层偏小（像声音忽大忽小）。RMSNorm 把每层输入"调回标准音量"，训练才能稳定。
- 细节：是对**整行 896 个数**求均方根，eps=1e-6 加在 mean 之后（防止除零）。
- 参考实现已在 `kernels/rmsnorm.cu`，看懂它，后面所有 kernel 照这个风格写。

### ③ QKV 投影：三次矩阵乘法（GEMM）

每个位置的 896 维向量，分别乘三个矩阵，得到三种"角色"：

- **Q（Query，我在找什么）**：896 → 896 维，14 个头 × 64
- **K（Key，我是什么标签）**：896 → 128 维，2 个头 × 64
- **V（Value，我口袋里装的内容）**：896 → 128 维

- 形象：把每个词派去参加一场"联谊会"。Q 是它想打听的问题，K 是它胸口的名牌，V 是它实际带来分享的信息。
- 为什么 K/V 只有 2 份而 Q 有 14 份：这就是 **GQA（分组查询注意力）**——14 个提问者共用 2 个档案柜。省显存的关键设计，也是你要在 kernel 里处理的映射：第 `h` 个 Q 头用第 `h/7` 个 KV 头。
- 你要做的：三次 cuBLAS GEMM（见第 5 节的转置大坑）+ 可能有 bias。

### ④ RoPE：盖位置邮戳

attention 本身是"一堆向量互相打分"，**天生不知道谁在前谁在后**（"法国的首都"和"首都的法国"对它一样）。RoPE 按位置把 Q、K 的向量**旋转一个角度**：第 0 个词转 0°，第 1 个词转一点，第 p 个词转 p 档。转完之后，两个词做点积时，角度差自动编码了它们的**相对距离**。

- 数学（rotate-half 约定，和 Llama 相同）：64 维两两配对——第 j 维和第 j+32 维为一对，一起旋转：
  ```
  q'_j      =  q_j · cos(θ_pj) - q_{j+32} · sin(θ_pj)
  q'_{j+32} = q_{j+32} · cos(θ_pj) + q_j · sin(θ_pj)
  其中 θ_pj = p · (1e6)^(-2j/64)
  ```
  高频维（j 小）转得快，管"相邻词"的精细关系；低频维（j 大）转得慢，管"远距离"的关系。
- V **不转**（它只被加权平均，不参与打分）。
- 工程建议：cos/sin 两张表 `[max_seq, 32]` 在 Engine 构造时一次算好放显存，forward 里只查表——为什么比每次现算好？（想想这个 kernel 会被调用多少次）

### ⑤ Attention：开会

现在是重头戏。对每个位置的每个 Q 头：

```
第 i 个位置（拿 Q）→ 和前面所有位置（拿 K）逐个算相似度（点积）
→ 相似度过 softmax 变成"注意力权重"（加起来=1 的百分比）
→ 按权重把前面所有位置的 V 加权平均 → 这就是第 i 个位置的新向量
```

- 形象：每个位置开一次会，环顾前面所有同事，越"相关"的同事（Q·K 分高）他的发言（V）权重越大。每个位置听完会，带走一份加权的信息汇总。
- **Causal mask**：只能看前面，不能偷看后面（j > i 的分数设为 -inf，softmax 后权重恰好为 0）。训练时全句一起算靠它保证"未来信息泄漏"，推理时天然也只用得上它。
- **注意 softmax 只在 j ≤ i 的有效范围里归一化**——被 mask 掉的 -inf 不能进分母（想想 `exp(-inf)=0` 但 `-inf - (-inf) = nan` 的坑）。
- M1 允许最朴素的写法：分数全存 shared memory，softmax 先求 max 再求 exp 求和，两遍就两遍。FlashAttention 是 M3 的故事。
- 复杂度：O(seq²)。这就是"上下文越长越贵"的根源，也是 KV Cache（M2）和 PagedAttention（M7）存在的原因。

### ⑥ o_proj + 残差：散会归队

14 个头的输出拼回 896 维，再过一次 GEMM（o_proj），然后**加回主干**：

```
x = x + attention( RMSNorm(x) )
```

- 残差是深度学习的命根子：主干是一条"高速公路"，每层只在旁边支路上做加工，加工结果**加**回高速路而不是替换。这样即使 24 层里某层学得不好，信息也不会丢，梯度也能从深处一路流回浅层。
- ⚠️ 结构是 `x = x + attn(ln1(x))`：norm 只作用于"进支路的原料"，主干 x 原封不动参与相加。写成 `x = ln1(x) + attn(...)` 就错了（这是常见 bug 清单第 9 条）。

### ⑦ MLP（SwiGLU）：独自消化

attention 是"位置之间交流"，MLP 是每个位置**独立**地过一个小神经网络：

```
gate = x @ Wg^T          [seq, 4864]     "门控信号"
up   = x @ Wu^T          [seq, 4864]     "内容信号"
out  = silu(gate) * up                   silu(v) = v · sigmoid(v)
x    = x + out @ Wd^T                    投影回 896 维，又一次残差
```

- 形象：896 维的"意见"先放大到 4864 维的"展开工作区"里充分处理，再压缩回 896 维。gate 门控决定每个特征**放大还是抑制**（sigmoid 输出 0~1，像旋钮），两个支路相乘就是"带开关的内容"。
- 4864 是 896 的 5.4 倍——MLP 占了模型参数的大头（算算哪几个矩阵最大就知道了）。
- `swiglu` kernel 是纯逐元素操作，最简单的一个，写完很有成就感。

### ②~⑦ 循环 24 次

以上是一个 decoder 层。同样的结构、**不同的权重**，重复 24 层。每一层都在对"理解"做精炼：浅层大概在处理语法和词形，深层在处理语义和逻辑（这是社区对可解释性研究的粗略总结）。

### ⑧ final RMSNorm + lm_head：交卷

最后一层输出后：再做一次 RMSNorm，然后把最终的 896 维向量与 **151936 个词牌逐一打分**（一次 GEMM：`[1,896] @ [896,151936]`），得到 151936 个 logits。分数最高的就是模型认为最该出现的下一个词。

- 打分用的矩阵就是 ① 里的 embedding 表（`tie_word_embeddings`：读和写共用一张表）。所以 M1 你只需要最后一个位置的 logits——前面位置的白算了？不，attention 需要它们。但 lm_head 只需要最后一行，这是个小省法。
- 金标准里 greedy_next 就是最高分对应的词。对拍时第一对比的就是它。

## 3. 张量形状速查（贴在手边）

```
seq = 5（"The capital of France is"）
x        [5, 896]     全程的主干
Q        [5, 14, 64]  → 摊平 [5, 896]
K / V    [5, 2, 64]   → 摊平 [5, 128]
scores   [14, 5, 5]   每个 Q 头一张 5×5 的相似度表（下三角有效）
attn_out [5, 896]
gate/up  [5, 4864]
logits   [151936]
```

每一层你都在这些形状之间搬运。**写任何 kernel 之前先在注释里写下输入输出形状**——一半的 bug 在写形状注释时就会自己暴露。

## 4. 为什么必须"逐层对拍"（M1 的灵魂）

### 没有"像人话"这种验证

输出流不流畅和算得对不对**几乎无关**——权重错一点点，模型照样流畅地胡说八道。而你错了 24 层里任何一层的任何一个下标，结果就全废。人眼无法判断，必须有客观的、逐层的标准答案。

### 工作流（脚本都已备好）

```
第 1 步  python scripts/golden_test.py            # HuggingFace 在 CPU 上用同一份权重
         # 把每条 prompt 的每一层 hidden state 存成 .bin —— 标准答案卷

第 2 步  你的 tli_test 也把每一层 dump 成 .bin     # 你的答卷（LayerHook 已经留好）

第 3 步  python scripts/compare_golden.py          # 逐层比 max|delta|
         # 输出"从第几层开始超差" —— 直接告诉你 bug 在哪一层
```

### 误差怎么判读（背下来）

| 层 | 正常范围 | 说明 |
|---|---|---|
| L0（embedding）| < 1e-6 | 纯查表，必须精确相等 |
| L1~L5 | < 1e-5 | 浅层累积少 |
| 深层 | < 1e-4 正常，1e-4~1e-3 可接受 | CPU/GPU 求和顺序不同，浮点误差自然累积 |
| 任何层 > 1e-3 | **有 bug** | 误差是会滚雪球的：第 3 层的小错到第 24 层就是灾难 |

**第一处超差的层就是案发现场**。该层只有 6 个算子，把中间量（norm 后、QKV 后、RoPE 后、attn 后、MLP 后）分别 dump 出来二分，10 分钟内锁定。

### 这套东西本身就是面试素材

"我怎么保证从零写的前向是对的"——能讲出金标准、误差预算、二分定位的候选人极少。
比"我调了 API 实现了 XX"高一个段位。

## 5. 最大的坑：cuBLAS 的行主序（先懂再写）

- PyTorch（和你脑子里的线性代数）是**行主序**：`y = x @ W^T`。
- cuBLAS 是**列主序**（Fortran 传统），文档里全是 `A^T`、`lda`，第一次看会怀疑人生。
- 好消息：行主序的 `A(m×k)` 在内存里**恰好等于**列主序的 `A^T(k×m)`。所以不用任何显式转置，`y[n,o] = x[n,h] @ W[o,h]^T` 对应：

```cpp
cublasSgemm(handle, CUBLAS_OP_T, CUBLAS_OP_N, o, n, h,
            &alpha, W, h,   // A = W 存储，OP_T，lda=h
            x, h,           // B = x 存储，OP_N，ldb=h
            &beta,  y, o);  // C = y 存储，ldc=o
```

- **动手前在纸上推一遍**（用 2×3 小矩阵，把内存排成一串数字，按列主序重读一遍）——面试官真会问"cuBLAS 为什么这么传参"。推不动就回来问 ZCode。
- 症状识别：结果"形状对、大体像、数值错" → 99% 是这里。
